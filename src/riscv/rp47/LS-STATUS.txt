R-P47 -- the two R-P46 deferred faults FIXED + 1 more real util (false)
======================================================================

HEADLINE #1 (DONE, boot-verified -smp 2): the FULL `ls -l` output/cleanup path
no longer SIGSEGVs at exit.

  ROOT CAUSE (bisected in R-P47):
    R-P46 printed the -l line ("... Jan release") then took a SIGSEGV.  The
    fault PC was inside the reduced libc `free` reached from `fclose`, at the
    exit-time atexit hook `close_stdout` (gnulib).  `close_stdout` does
    fclose(stdout); the reduced libc `fclose` (libc/port/stdio2.c) then
    UNCONDITIONALLY called free() on the FILE.  But stdin/stdout/stderr are
    STATIC FILEs (`&__stdout`, with a static `__out_buf`), NOT heap blocks.
    free(&__stdout) computed a bogus block header (`&__stdout - HDR`), and the
    first-fit allocator's forward-coalesce then dereferenced a clobbered `next`
    pointer -> a load fault.  (This is why the +FORMAT / default -l runs faulted
    at exit but the earlier utils that never fclose(stdout) did not.)

  THE FIX (one place, all callers -- libc/port/stdio2.c + stdlib.c):
    * fclose() now frees only a HEAP stream: it skips free() (and the buffer
      free) for stdin/stdout/stderr.  This matches glibc/illumos -- the standard
      streams are never freed on fclose.  Every close_stdout/atexit caller
      benefits.
    * free() (libc/port/stdlib.c) also gained a defensive heap-bounds guard
      (ignore a pointer outside [__heap_head, __brk_cur)) + a coalesce-target
      sanity check, so a stray non-heap free can never fault the allocator.

  PROOF (rp47/qemu-boot.log, boot-verified -smp 2):
    /bin/lsup -l --time-style=+%b /etc  ->
        total 1
        -rw-r--r-- 1 0 0 44 Jan release
        [exit 0]
    The REAL UNMODIFIED ls prints the whole long line (mode / nlink / owner /
    group / size / MONTH / name) AND exits cleanly.  (R-P46: month printed,
    then SIGSEGV.)

HEADLINE #2 (DONE, boot-verified -smp 2): `yes | head` over a closing pipe no
longer faults the kernel.

  ROOT CAUSE (bisected in R-P47):
    `head -3` reads 3 lines then exits, closing the pipe read end.  Before the
    writer even hit the closed pipe, the kernel took a synchronous load fault:
        [trap] scause=0xd sepc=<fop_getattr> stval=0x0
    `head` (and `yes`) fstat their stdin/stdout up front; the pipe fd has
    f_pipe set and f_vnode == NULL, but proc_fstat (kernel/proc.c) called
    fop_getattr((vnode*)f_vnode) unconditionally -> fop_getattr's `ld 0(a0)`
    with a0==NULL -> a NULL-vnode load fault that halted the kernel.

  THE FIX (kernel/proc.c):
    * proc_fstat + proc_lseek now GUARD pipe fds: fstat of a pipe reports a
      char-special of size 0 (no NULL-vnode deref); lseek of a pipe returns
      ESPIPE.  (The read/write paths already routed pipe fds to
      pipe_read/pipe_write.)
    * pipe_write() now POSTS SIGPIPE (sig 13, default action = terminate) to
      the writer via proc_kill(curpid, SIGPIPE) when the readers hit 0, and
      returns EPIPE.  Delivery happens on the trap-return edge
      (proc_deliver_signals), so the writer dies gracefully instead of spinning
      or faulting in the teardown.  SIGPIPE (13) + EPIPE (-32) added to proc.c.

  PROOF (rp47/qemu-boot.log):
    /bin/coreyes | /bin/corehead -3  ->
        ...
        [signal] sig 13 default action: terminate pid 48
    $ echo pipe-survived
    pipe-survived
    yes takes SIGPIPE when head closes the read end; the shell survives to run
    the next command; NO [trap] halting.
