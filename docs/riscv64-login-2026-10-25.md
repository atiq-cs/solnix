# riscv64 uts: a key-only remote login with dropbear (rvlogin, 2026-10-25) -- DRAFT

From the host, through qemu user-net `hostfwd`, at -smp 8:

    ssh -p 2522 -i ~/.ssh/id_ed25519 gburd@127.0.0.1 'uname -a; echo $((6*7))'
    SunOS solnix 5.11 solnix riscv64
    42

This worked on 4/4 boots. A wrong key was refused on 4/4. Base: HEAD 6896202. Everything was built natively on lixr
and run there under qemu 10.2.1; floki only edited files and ran the ssh client. Diff: `/scratch/solnix/rvlogin/uts.diff`,
with changed and new files under `files/`. Nothing is committed.

## What changed, and the test for each piece

Every test calls the kernel with raw `ecall`s, so the libc glue is not in the path. Each one fails on the HEAD kernel
(`unix-base`) and passes on `unix-d1`, one boot each at -smp 8.

| Piece | Kernel change | Test | HEAD | unix-d1 |
|---|---|---|---|---|
| entropy | new `uts/viornd.c`: a virtio-rng driver (VirtIO 1.2 §5.4, one queue, polled) and `getrandom` (278), up to 4096 B per call, flags checked, `copyout`. **There is no fallback**: with no device, getrandom returns ENOSYS. | `tests/rndtest.c`: two 4 KiB draws differ, all 256 byte values appear, chi² < 400, bad flags give EINVAL, a kernel pointer gives EFAULT. Control `rnd-none.checks`: qemu without `-device virtio-rng-device` must give ENOSYS | `RNDTEST FAIL short draw r=-1` | `RNDTEST PASS values=256/256 chi2=254/255`; control `PASS (no device: ENOSYS)` |
| sessions | `p_sid`/`p_pgid`; `setsid` (157, EPERM for a group leader), `getsid` (156), `getpgid` (155) | `tests/sidtest.c` | `FAIL child setsid/...` | `SIDTEST PASS` |
| wait4 WNOHANG | `proc_waitpid(..., nohang)`: returns 0 while children are alive; any other option bit gives EINVAL | sidtest (0 while the child lives, then the reap) | (same failing test) | PASS |
| O_NONBLOCK | per-fd `fd_nonblock`; `fcntl` F_GETFL (3) and F_SETFL (4); read/write on a pipe or socket that is not ready gives EAGAIN; the console refuses with ENODEV, which dropbear tolerates | `tests/nbtest.c` part 1 | `FAIL F_SETFL O_NONBLOCK r=-22` | `NBTEST PASS` |
| poll EINTR | `proc_poll` returns EINTR instead of waiting when a signal that has a handler, or that kills by default, is pending | nbtest part 2: poll(-1) on an empty pipe, a child exits, the SIGCHLD handler runs | (same) | PASS |
| credentials | real, effective and saved uid/gid with the POSIX rules (privileged means euid 0); `setresuid`/`setresgid` (147/149), `geteuid`/`getgid`/`getegid` (175/176/177). **Security fix:** at HEAD `setuid` was unchecked, so any process could call `setuid(0)` | nbtest part 3: root's seteuid round trip works; after `setuid(1000)`, both `setuid(0)` and `setresuid(-1,0,-1)` give EPERM | (same) | PASS; the one-uid kernel `unix-c1` gives `FAIL ... r=8` |

Every piece came from running dropbear, apart from the two the plan predicted (entropy, setsid):
* `Failed to revert euid`: one uid per process, so there was no way back from `seteuid(user)`.
* `while (read(sigpipe) > 0)`: needs O_NONBLOCK, or it hangs.
* The SIGCHLD handler: needs poll to return EINTR.

## dropbear

* Version: 2025.88 (MIT), `https://matt.ucc.asn.au/dropbear/releases/dropbear-2025.88.tar.bz2`.
* sha256 `783f50ea27b17c16da89578fafdb6decfa44bb8f6590e5698a4e4d3672dc53d4`. It matches upstream's
  `SHA256SUM.asc`; the GPG signature was not checked.
* Build: `pkg/build-dropbear.sh` with `pkg/dropbear-localoptions.h`. It uses `solnix-cc`, bundled libtom, no zlib, PAM,
  syslog or utmp.
* Output: a static ET_EXEC at 0x40010000 with two PT_LOADs (r-x, rw-). `dropbear` is 375080 B and `dropbearkey`
  215968 B. Every compiler warning is `-Wsign-compare`; there are no implicit declarations.
* Compiled options: server only, ed25519 only, `DROPBEAR_SVR_PASSWORD_AUTH 0`, and no agent, TCP or X11 forwarding.
  Host key path `/data/dropbear_ed25519_host_key`.
* Run as `dropbear -F -w -j -m -P /tmp/dropbear.pid -p 22 -r <key>`. `-w` refuses root logins.
* `__linux__` is undefined in dropbear's CFLAGS, because the board's gcc predefines it. It is not changed in solnix-cc,
  so the other packages are unaffected.

**libc work (`pkg/solnix-libc`)**:
* Before this, the sysroot had no socket API at all. The first configure failed on `socklen_t`.
* New `net.c`:
  * the BSD socket calls [REAL];
  * `select` over poll [DERIVED];
  * `readv`/`writev` [DERIVED, not atomic];
  * a numeric-only `getaddrinfo`/`getnameinfo` [DERIVED; there is no DNS];
  * `syslog` writes to stderr;
  * `initgroups`/`setgroups`/`getusershell` [STUB];
  * `getrlimit`/`setrlimit` [STUB];
  * `shutdown` [ENOSYS].
* New headers: `sys/{socket,uio,un,resource,random}.h`, `netinet/{in,tcp,ip,in_systm}.h`, `arpa/inet.h`, `netdb.h`,
  `syslog.h`.
* `glue.c`: setsid, getsid, getpgid, getrandom, getentropy, geteuid, getgid, getegid, setresuid, setresgid,
  F_GETFL/F_SETFL and WNOHANG now go to the kernel.
* **Bug found:** newlib's `uid_t` is `unsigned short`, so `(uid_t)-1` arrives as 0xffff, which the kernel reads as
  uid 65535. `KID()` maps it back to -1.

**Session root** (`pkg/stage-dropbear.sh`):
* `/etc/passwd` has root and gburd (uid 1000, home `/home/gburd`, shell `/bin/sh` = dash).
* floki's `~/.ssh/id_ed25519.pub` is installed as `/home/gburd/.ssh/authorized_keys`.
* pkginit runs `dropbearkey -t ed25519` into `/data` on first boot, then dropbear in the foreground.

## Proof (`proof/summary.txt`, guest logs on lixr `~/scratch/rvlogin/logs/ssh-p8-{1..4}.log`)

`work/sshproof.sh` on floki and `work/sshboot.sh` on lixr. The client reaches lixr's loopback forward through
`ProxyCommand ssh lixr -W 127.0.0.1:2522`, so floki's private key never leaves floki. qemu is stopped by its exact pid.

| -smp 8, unix-d1 | boot 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| right key: `uname -a; echo $((6*7))` | `SunOS solnix 5.11 solnix riscv64` / `42`, exit 0 | same | same | same |
| **wrong key (control)** | `Permission denied (publickey)`, exit 255; guest: `Exit before auth` | same | same | same |
| right key: `whoami` | `gburd` | same | same | same |
| interactive, no pty (`ssh -T`, commands on stdin, `exit 5`) | `s1 9`, `authorized_keys`, exit 5 | same | same | same |
| `ssh -tt` (pty request) | `PTY allocation request failed`, exit 255 | same | same | same |
| guest: connections / pubkey OK / refused before auth / traps / panics | 5 / 4 / 1 / 0 / 0 | same | same | same |

**Entropy control.** With no virtio-rng device, both `dropbearkey` and `dropbear` exit with `Failure reading random
device /dev/urandom`. No server starts on weak randomness (`logs/ssh-norng-1.log`).

**Two harness traps fabricated a passing wrong-key control before it was trusted:**
1. floki's ssh config has `ControlMaster auto` and `ControlPersist 600`. Runs 2 and 3 reused run 1's authenticated
   connection, and the guest logged one connection for three ssh commands.
2. The same config adds `IdentityFile ~/.ssh/id_ed25519` and an agent, so the "wrong key" run also offered the real
   key. The guest showed the real key's fingerprint SHA256:m19QO….

The client now runs with `-F /dev/null`, `ControlMaster=no` and no agent. Only then did the control fail as it should,
with a separate guest connection per command.

## What is not done

* **ptys.** `ssh host cmd` and a no-pty shell over `-T` work. An interactive terminal (`ssh host` with a pty) is
  refused cleanly. A pty pair plus termios and a controlling tty is the next item: two byte rings like the pipe, plus
  per-pair termios and TIOCGWINSZ.
* Host-key persistence across boots was not tested: every proof boot had a fresh `/data`. `fsync` is ENOSYS; dropbear
  warns and continues.
* No `shutdown(2)`, no supplementary groups, and `readv`/`writev` are not atomic.
* Signals still use the Linux numbering via the glue translation.
* `getrandom` holds a spinlock with SIE off while it polls the device (one request in flight). An IRQ-driven
  completion is the upgrade.
