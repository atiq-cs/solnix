## rvsmp-1b: real SMP

- proc.c `runq_enqueue` calls `smp_wake_idle()` (seq_cst fence, claims one idle hart, IPIs it).
- The secondary idle loop masks SIE, sets its idle bit, rechecks the runq, then wfi. This loses no IPI.
- timer.c `clock_start_secondary`: a per-hart tick. Secondaries only rearm their own deadline.
- Result: 4/4 boots at -smp 8 trapped at `swtch+0x86` (S-mode load PF, stval=0x2). A control with the IPI alone,
  no tick, failed 3/3 the same way.
- Mechanism: `thread_yield` enqueued itself before `rv_swtch` had saved its context, so an IPI-woken hart ran the
  same kernel stack at the same time.

## rvsmp-a: deferred enqueue (hazard a)

- Per-hart `swtch_prev[MAXCPU]` plus `swtch_tail()`, run where a thread resumes (after both `rv_swtch` calls and
  in `rv_thread_start`). The next thread enqueues the old one only after the old context is stored.
- Kernel-mode traps at -smp 8 went from 4/4 boots to 0/10.
- smpstress still never ran: 7/10 boots took U-mode store faults on the user stack after the first fork, i.e.
  hazard b.

## rvsmp-b: per-hart curproc and lofault, then sleep/exit publication

- Fix 1:
  - `curproc` is now per-hart (`curproc_hart[MAXCPU]` indexed by tp).
  - `swtch` restores the resumed thread's own proc. Before, it used the pre-switch cpu's current thread.
  - `copy_lofault` is per-hart (trap.c, copy.S, swtch.S).
  - Result: smpstress -smp 8 6/6 PASS, par 6.77-7.09 (before: 0/10 reached smpstress). Gates -smp 8: login 6/6
    (before 0/6).
- Fix 2: the same early-publish race as hazard a, in `sleep_on` and `thread_exit`.
  - `t_swtch` plus `swtch_sleep`/`swtch_dead`: the thread is published in `swtch_tail`.
  - `wakeup` skips the enqueue while `t_swtch` is set.
  - `thread_reap` waits for TS_DEAD.
  - Result: gates 8/8 x6 at -smp 8.
- check-all at -smp 8 then showed two new signatures:
  - `exit=-1` after a clean child exit;
  - kernel lines interleaved character by character.

## rvsmp-c: SUM per hart, console line owner

- (A) `exit=-1`: instrumentation showed wait4 reaped the right pid, but `copyout(status)` failed with EFAULT.
  All 13 failing copyouts ran with sstatus.SUM=0. sstatus is per-hart and not part of the thread context, so a
  thread that resumed in the kernel on another hart inherited that hart's SUM.
  - Fix: `dispatch_init_cpu` sets SUM on every hart (proc.c:~793).
  - Result: `exit=-1` 0 in 2 runs (before: 7-14 per run).
- (B) The console has a per-line owner (sbi.c `cons_owner`: a CAS on the first char, released on `\n`, stolen
  after 100 ms).
  - Result: split kernel lines 0 in 2 runs. sbase went from 16-17/31 to 31/31.
- Left: smpstress 11/12, a 1/12 pipe-tag signature, and 90-91/92 at -smp 8.

## rvsmp-d

### 1. Pipe slot / pid claims (FIXED)

- Signature on unix-c: in boot 9 of t12, children 7 and 8 read each other's tags for the whole run, i.e. they
  shared one pipe. Rate on unix-c: 1/60 boots (t12 + t15 control).
- Counting probe with an atomic exchange on `p_inuse`/`pp_used` and a print on a double claim: 0 double claims in
  144 boots, which also all passed. At 1/60 that count cannot tell us anything.
- Proof: a 200 us spin between `pipe_alloc`'s test and its claim (unix-ddbg3) produced 1 `[dbl] pipe slot double
  claim` in 6 boots. That boot failed smpstress with the same signature: a child read another child's tag, then
  `write(bad)`.
- Fix, uproc.c:
  - `pipe_alloc` claims `pp_used` with `__atomic_exchange_n` and skips the slot if another hart got it first.
  - `proc_alloc` claims `p_inuse` the same way, before it zeroes `p_uframe`.
  - `p_pid = __atomic_fetch_add(&next_pid)`.
  - This is a lock-free claim, not a new spin lock: uproc.c has no proctab lock to reuse, and one exchange per
    slot is the smaller change.
- Result (unix-d1): smpstress -smp 8 48/48 PASS, par 6.60-7.39, trap 0.
- Found along the way, not fixed: unix-c control boot 29 (1/48) took a U-mode instruction PF at
  sepc=stval=0x8020016e.
  - That address is the instruction right after `csrw sepc` in trap.S's restore (trap.S:173-175).
  - Reading, not proven: an interrupt taken between `csrw sepc` and `csrw sstatus` overwrites sepc. SIE can be 1
    there because sstatus is per-hart and the secondary idle loop runs with SIE=1. This is the same class of bug as
    SUM.
  - Candidate fix: `csrci sstatus, 2` before trap.S:173.
  - Rate on unix-d1: 0/48 (with no widening, that says little).

### 2. ncurses byte-oracle (OPEN; the brief's premise refuted)

- The text inside curstest's block is not `[fork]/[exec]/[exit]`. byte-oracle.py:17 and run-checks.sh:105 already
  strip those.
- It is the boot hart's banner:
  - `[R-P6] root on` (rootfs.c:269);
  - `[startup] startup complete`/`freelist` (startup.c);
  - `[R-P5]/[R-P6]/[R-P8]` (main.c:612-620).
- At -smp 8, `single_user_thread` runs /sbin/init on a secondary while hart 0 is still printing these, so they
  land in the first test block of the run. At -smp 1 they print after RVPKG DONE.
- Correlation: replaying byte-oracle over 13 earlier check-all logs, every DIFFER log (4/13) has 4-7 banner lines
  in the block and every EQUAL log (9/13) has 0. On unix-d1, all 4 check-all failures in 2 runs (sbase echo,
  ncurses byte-oracle, fs ls-t, dash dash-script) are 7 banner lines in the first `%`-oracle block of that suite.
- Removing the per-event lines would not fix it, so they stay. The gate PASS lines are untouched.
- Tried: init waits for the banner.
  - main.c sets `boot_banner_done` and calls wakeup; `single_user_thread` sleeps on it in a new `sleep_on_unless`
    under the runq lock.
  - That kernel (unix-d3, 166f79a6, sources in `/scratch/solnix/rvsmp/fix2-d3/`) made byte-oracle EQUAL 2/2 and
    left fs with 0 banner lines.
  - But it **hangs the boot**: smpstress at -smp 8 hung 3/12, at -smp 1 2/2, and check-all/fs/gates boots 4/24.
    The last line is `SINGLE USER MODE`, with no `[R-P8]` banner, so the boot thread (`idlethread[0]`) never ran
    again.
  - **Reverted.** The hang is deterministic at -smp 1, so it is easy to chase.
  - The first attempt, unix-d2 (yield-polling), hung on every boot: hart 0's boot code is `idlethread[0]`, and
    `thread_yield` from a non-idle thread returns at once on an empty runq (proc.c:589).
- Next options:
  - (a) find why `idlethread[0]` is not rescheduled once its only competitor sleeps, then keep the wait;
  - (b) print the banner before `single_user()` creates the thread (move main.c:612-620 and rootfs.c:269 ahead of
    thread creation);
  - (c) have the harness drop banner lines, as it already does for `[fork]`.
  - (b) is the smallest change.

### 3. fs xfail-fs-exit (NOT A BUG: the harness's negative control)

- `RVPKG END xfail-fs-exit exit=1 want=0 FAIL` appears in every fs run, -smp 1 included. That is

- The run that was counted as failing (fs failed=1) had 7 banner lines in `ls-t`'s block (fs.checks:6-7, the first
  `%` check): the same cause as fix 2.
- Rate:

  - unix-d1 check-all: fs failed=1 in r1 (ls-t banner), 0 in r2.

## Final step (rvsmp-e, 2026-10-25): check-all green at -smp 8

- The banner: single_user() now runs from main() after the [R-P8] line, and the "[R-P6] root on <dev>" line prints
  before the init thread is created. The post-yield "did not report in" check is gone (it always printed after init
  started and misreported at -smp 8). Boot order: [R-P8], [R-P6] root on, [init], RVPKG INIT.
- trap.S: `csrci sstatus, 0x2` before the sepc restore. A secondary's idle loop enables SIE and then switches to a
  thread that resumes inside trap(); SIE is per hart and not saved with the thread, so the return path could run with
  interrupts on and an interrupt between `csrw sepc` and `csrw sstatus` would clobber sepc (the 1-in-48 fault at
  0x8020016e). The restored sstatus has SIE clear; sret re-enables it from SPIE.
  0 such faults in 67 boots does not prove it (0/67 happens ~25% of the time unfixed); the fix rests on the mechanism.
- Rates (kernel unix-e1, md5 7c20f22c): check-all -smp 8 x2 8/8 suites failed=0 (93 checks), -smp 1 8/8;
  smpstress -smp 8 12/12 (par 6.77-7.66); gates -smp 8 8/8 x4, -smp 64 8/8 x2; 0 unexpected traps in 67 boots.
